# LocalFlow

A personal, fully-local voice-to-text dictation tool for Windows (a Wispr Flow clone). Hold a hotkey, speak, release, and the text is typed into whatever app has focus. Transcription runs locally on the Intel Arc iGPU. No audio or text ever leaves the machine.

Built and owned by Jeremy. This is a **personal tool**, not a product for distribution.

The design took three live-feedback iterations; the survivors are LOAD-BEARING, do not reintroduce the deleted machinery: (1) the committed stream is APPEND-ONLY — a word types once two consecutive decodes agree (`core.live.commit_prefix`, LocalAgreement-2) and is then FINAL; there is NO final patch, NO freeze tail, NO revision pass (all deleted — the remaining corrections are the silence take-back, which erases everything typed when the final pass produced nothing, and the boundary-punctuation edit (Jeremy OK'd punctuation-only edits 30 Jul): the trailing mark of the last typed word (any of .,!?;:) stays provisional until the next words arrive, then is added/replaced/removed to match the same word's surface in the newer decode or authoritative segment text (norm-guarded; cross-cut fallback: drop a trailing .!? before a lowercase continuation) — words are still never revised). (2) Injection is TARGET-LOCKED: the focused control HWND is captured at dictation start (`inject.focused_control`) and live typing is POSTED to that HWND, so the stream keeps landing in the original field when focus moves; dead target = drop, never spill (same-window browser tabs share one Chromium HWND — the stream follows the visible tab there, known limit). (3) Backspace style is picked by window class (`inject._keydown_deletes`): classic edit controls need WM_CHAR 0x08 (FIFO with posted text — a raw VK_BACK keydown gets its WM_CHAR enqueued BEHIND already-posted text via the target's own TranslateMessage and corrupts the stream), Chromium/Gecko need the key-down pair; WPF/Qt fit neither list — extend the tuple if one surfaces. (4) Key suppression is FOCUS-SCOPED: only keys headed into the target field are swallowed, the keyboard stays alive everywhere else; Esc cancels only from inside the target; no target info = full lock. (5) Order is sacred: after a Tier 1 cut the preview pauses until that window's segment text lands its tail via `LiveTyper.on_segment_text` (the only post-release typing path — the worker calls it for the final segment too). Cleanup LLM + dictionary do NOT reach the screen on live-typed dictations (no correction pass exists); they only shape history/last_text.

## Hard constraints (from the PRD, do not violate)
- **Fully local.** No network calls for transcription. No cloud speech-to-text. No audio or text leaves the device.
- **The core seam.** `localflow/core/` is a pure Python package: audio in, text out. It must NOT import the desktop layer, touch the clipboard or keyboard, or make network calls. This is the seam that lets FARA and other projects reuse the exact same transcription code later.
- **The hardware.** Target machine is an Intel Core Ultra (Lunar Lake), Intel Arc 140V iGPU + NPU. No NVIDIA, no CUDA. Log which device (GPU / NPU / CPU) actually ran at startup.
- **Ollama cannot transcribe.** It is only ever the optional cleanup LLM (removes filler words, fixes punctuation). The transcriber is Whisper on OpenVINO.

## Scope

- Phase 2 (FARA web integration) and Phase 3 (cloud) are DESIGNED FOR but NOT BUILT in v1. Keep the core seam clean; build nothing for them yet.
