# LocalFlow v1.2 Plan - Live dictation typing (planned 27 July 2026)

Three milestones, M11 to M13, continuing v1.1's numbering. Each independently
shippable and committed on its own. Build in order; each depends on the last.

Research behind this: `docs/stt-streaming-research.md`. Short version: Google's
edge is streaming architecture + two-pass rescoring, not raw accuracy. We
replicate the feel with a re-decode-and-commit loop on the existing OpenVINO
Whisper turbo engine (~50x realtime on the iGPU makes a ~1s re-decode cadence
affordable). No new models, no new deps.

## What Jeremy asked for (locked decisions, grilled 27 Jul)

- Dictation TYPES committed words directly into the focused app ~1-2s behind
  his voice (Google Docs feel), not an overlay preview, not paste-at-end.
- BOTH modes stream: tap alt+` (or click the pill) = toggle on/off; hold
  alt+` = same streaming, ends on release.
- Keyboard fully suppressed while dictating (except alt+` = stop, Esc =
  cancel). This is what makes mid-hold injection clean: suppression + clearing
  the app-visible modifier state at start means apps never see Alt held.
- Committed words ONLY are typed (two consecutive decodes agree,
  LocalAgreement-2). No provisional churn in the target app.
- On stop: normal final pass (join + hallucination filter + dictionary +
  cleanup if on), diff vs typed, backspace the divergent suffix, retype.
  Final quality identical to v1.1.
- Esc cancels: stop immediately, skip the final patch, typed text stays.
- `live_typing = true` default (toml + Settings checkbox). false = EXACTLY
  v1.1 behavior: hold-to-talk, paste on release, no suppression, no toggle.
- Focus change mid-dictation: typing follows focus (same as Google). Known
  behavior, not a bug.

## Hard constraints carried forward

- Engine strictly single-threaded (`app.engine_lock`). Preview decodes skip a
  beat when a segment/final decode holds the lock, never queue behind it.
- Preview decodes use fast settings: no timestamps, no hallucination filter
  (those run on the final pass only).
- Tier-1 segmenter unchanged: a cut segment's raw text commits wholesale and
  the preview window restarts after the cut. `_produce_lock` ordering rules
  stay exactly as they are.
- `localflow/core` stays pure: the new commit/diff logic goes there as pure
  functions; injection and hooks stay in `localflow/desktop`.

## M11 - Interaction shell: toggle mode + keyboard suppression

Goal: tap-toggle and hold both work, keyboard dead while dictating, Esc
cancels. Output still v1.1 paste-on-release (no streaming yet). De-risks the
OS-level scary part first.

Changes (`localflow/desktop/app.py`, `capture.py` or a new small
`livekeys.py`):
1. Tap vs hold: keydown always starts recording (pre-roll already protects
   the first words). Keyup within ~300ms = tap -> keep recording (toggle
   mode), next tap (or Esc) ends it. Keyup after 300ms = hold -> finalize as
   today. Pill click = same toggle path.
2. Suppression: while dictating, a low-level hook (`keyboard` lib,
   suppress=True) swallows all keys except our stop/cancel keys. Installed on
   dictation start, removed on stop. Hooks die with the process, so a crash
   cannot leave the keyboard dead. Mouse untouched.
3. Modifier clearing: on dictation start, send synthetic key-ups for any
   app-visible held modifiers (Alt from the hotkey), so the OS modifier state
   is clean for later injection.
4. Esc during dictation = cancel: stop recording, discard audio, no paste.
5. Mic test / Calibrate never suppress (they own the recorder, not the
   keyboard).

NOT doing: any streaming, any live injection, config key (M13).

Definition of done:
- Live: while dictating, typing on the physical keyboard does nothing in the
  focused app; alt+` tap toggles on/off; hold still pastes on release; Esc
  cancels with no text.
- Unit tests for the tap/hold state machine (pure timing logic, no OS).
- All existing tests pass.

### M11 build log (27 Jul 2026) - CODE COMPLETE, live DoD pending Jeremy

- Suppression uses **pynput**, not the `keyboard` lib the plan named: pynput
  is already a dependency and does the same job via
  `Listener(win32_event_filter=...)` + `suppress_event()`. No new dep.
- `TapHoldGate` (`app.py`) is the pure state machine: key_down / key_up /
  click / cancel -> START | STOP | CANCEL | NONE. Tap window `TAP_MAX_S` =
  0.3s. A tap latches; the second tap ends it on the DOWN (its up is
  swallowed). It also swallows the key-up of a refused start, which replaced
  the old `_hotkey_suppressed` flag.
- `PushToTalkListener._win32_filter` owns the keyboard while
  `app.suppress_keys` is set. Three outcomes: `True` = key reaches the app
  AND our callbacks (idle), `False` = the app only (INJECTED events, i.e.
  our own typing and the modifier clear), `suppress_event()` = nobody. The
  hotkey and Esc are dispatched from inside the filter and swallowed too, so
  the app never sees the hotkey's Alt auto-repeat re-asserting the modifier.
  Any error in the filter fails OPEN.
- `_combo_vk_map` turns the parsed combo into raw vk codes (the hook reports
  vks, and left/right Alt differ). Verified for alt+`, ctrl+space, f9,
  ctrl+shift+d.
- `inject.clear_modifiers()` sends one synthetic release per held modifier at
  dictation start. That plus suppression is what makes M13's mid-hold typing
  clean.
- Esc -> `app.cancel_dictation()`: always clears suppression (escape hatch),
  drops the audio, and queues a `_Segment(final=True, cancelled=True)` so the
  worker flushes any Tier-1 segments already accumulated instead of leaking
  them into the next dictation. Segments already on the queue still get
  transcribed, then discarded.
- `LocalFlowApp(suppress_keys=...)` is None for tests/embedders: no hook, no
  synthetic keys. `_run()` passes a real `threading.Event()`.
- Tests: 256 pass (was 248). New: gate hold/tap/cancel/click, app-level
  tap-toggle, Esc cancel, suppression lifecycle, filter routing.
- Live checks still owed: keyboard dead while dictating and alive after
  (including after a forced kill), tap toggles, hold still pastes, Esc leaves
  nothing.

## M12 - Streaming commit engine (log-only)

Goal: during a dictation, committed words accumulate ~1-2s behind speech,
visible in the log. No injection yet - proves cadence, contention, and commit
stability on real audio.

Changes:
1. `localflow/core/live.py` (pure, unit-tested):
   - `commit_prefix(prev_words, new_words, committed_len) -> int`: longest
     common word-prefix rule (LocalAgreement-2), never retreats below what is
     already committed.
   - `patch_plan(typed: str, final: str) -> (n_backspaces, retype)`: word-
     aligned diff for the M13 final patch.
2. `localflow/desktop/livetyper.py`: a preview loop thread (Segmenter-style,
   own poll cadence ~1s). Each tick: snapshot the recorder's uncommitted
   buffer, `engine_lock.acquire(blocking=False)` - skip the tick if busy -
   fast-decode, feed the hypothesis to `commit_prefix`, log newly committed
   words. On a Tier-1 segment cut, the segment's raw text commits wholesale
   and the window resets past the cut.
3. Committed stream = joined segment texts + committed prefix of the current
   tail, with consistent single-space joins (same rule the worker uses).

NOT doing: injection, patching, config. Cleanup/dictionary untouched.

Definition of done:
- Log from a real 60s+ dictation shows words committing steadily 1-3s behind
  speech, no commit ever retracted, no interference with segment cuts or the
  final paste (still v1.1 paste).
- Unit tests: commit_prefix (agreement, divergence, never-retreat), patch_plan
  (identical, suffix change, full rewrite), segment-cut window reset.

### M12 build log (27 Jul 2026) - CODE COMPLETE, live DoD pending Jeremy

- `localflow/core/live.py` (pure): `commit_prefix(prev, new, committed_len)`
  compares words NORMALISED (lowercased, punctuation stripped) - Whisper
  re-punctuates and re-capitalises as the buffer grows, so a strict match
  would almost never agree and nothing would ever commit. Never returns below
  `committed_len`. `patch_plan(typed, final)` is word-aligned and deletes back
  to the end of the last kept word, so the separating space is part of the
  retype (`"I rode a bike"` -> `"I wrote a book"` = 12 backspaces,
  `" wrote a book"`).
- `localflow/desktop/livetyper.py`: `LiveTyper`, Segmenter-shaped (own thread,
  own poll, reads the recorder only, never queues). Each tick: skip unless
  `is_dictating()` (recorder.recording AND not mic_test_active - Test mic and
  Calibrate also record), reset on a new `current_id()`, snapshot, skip under
  `MIN_WINDOW_S` (1.5s), resample OUTSIDE the lock, `engine_lock.acquire
  (blocking=False)` and SKIP the beat if busy, `engine.transcribe(timestamps=
  False)`, commit, log.
- Preview decodes deliberately skip preprocess AND the VAD/hallucination
  filter. Denoise on a growing window every second would eat the cadence; the
  final pass still owns quality (M13 patches the difference).
- Commit bookkeeping is `_regions` (windows the segmenter already cut away) +
  `_window` (the live one), concatenated. That split is what lets a cut
  segment's authoritative text land AFTER the new window has already committed
  words without reordering the stream. Reconciliation appends only the words
  the preview had not committed (count-aligned, `ponytail:` comment) so a
  commit never retracts.
- Three app touch points: `emit_segment` calls `on_cut(id)` inside the produce
  lock (a preview tick must never scan the drained buffer holding the pre-cut
  hypothesis); `_handle_segment` calls `on_segment_text(id, text)` for EVERY
  mid segment, silent ones included (reconciliation is in cut order, so
  skipping one would shift every later segment onto the wrong window); `_run`
  builds it beside the Segmenter, arms `engine` + `start()` after warmup, and
  stops it in the teardown. All events carry the dictation id and drop stale
  ones.
- End of dictation: the tick logs the stream once (`_flushed`) but KEEPS the
  state until the next dictation resets it, so a segment text still in flight
  lands instead of racing a teardown. M13 reads `livetyper.text()` for the
  patch.
- No config key yet (M13 owns `live_typing`), so the preview loop runs on
  every dictation. Known accepted cost: the final decode on release can wait
  up to one preview decode (~0.6s on a 30s window) for the engine lock.
- Tests: 271 pass (was 256). New `tests/test_live.py` (10: agreement,
  divergence, never-retreat, punctuation-insensitivity, the four patch shapes)
  and 5 LiveTyper tests in `tests/test_desktop.py` (commit cadence, busy-lock
  skip, short buffer + stale id, segment-cut ordering, flush/reset).
- Live check still owed: a real 60s+ dictation whose log shows words
  committing 1-3s behind speech, nothing retracted, segment cuts and the final
  paste unaffected.

## M13 - Live injection + final patch + config

Goal: the feature. Committed words typed into the focused app as they commit;
stop runs the final pass and patches the difference; config toggle.

Changes:
1. Typer: inject newly committed text via SendInput unicode (the existing
   `type` inject path in `capture.py` - reuse it, don't write a second
   injector). Backspaces via VK_BACK for the final patch.
2. On stop (toggle-off or hold-release): worker runs the normal final pass,
   then `patch_plan(typed, final)` -> backspace the divergent suffix, retype.
   Skip injection entirely if nothing diverges. Esc = stop with no patch.
3. Config `live_typing = true` (tomlkit, live-appliable), Settings checkbox
   "Type words live while dictating". false = the M11-M13 paths are bypassed
   entirely: v1.1 hold-to-talk + paste, no suppression, no toggle.
4. History/learning loop records the FINAL text (as today), not the live
   stream.
5. Pill: existing rec state covers live mode; no new overlay surface.

NOT doing: provisional-tail typing, overlay caption text, per-app injection
quirks beyond the sign-off list (document known-bad apps instead), Parakeet
A/B (separate task, see research doc), AlignAtt port (revisit only if the
1s cadence feels laggy in practice).

Definition of done (live sign-off, Jeremy):
- Notepad, a browser textbox, and VS Code: dictate a paragraph in toggle mode,
  words appear steadily, final patch leaves exactly the same text a v1.1
  paste would have produced (spot-check against a paste-mode run).
- Hold mode streams identically and ends on release.
- Esc mid-dictation leaves typed text, types nothing more.
- Physical keyboard suppressed during, alive after (including after a forced
  kill of the tray process).
- All tests pass.

### M13 build log (27 Jul 2026) - CODE COMPLETE, live sign-off pending Jeremy

- **The one load-bearing design change: the committed stream is now strictly
  APPEND-ONLY.** M12 let a cut segment's late text fill its region in place
  while the new window had already committed past it. That is fine for a log
  and impossible for typing - you cannot insert text into a document you have
  already typed past. So `_commit` now HOLDS while `_reconciled <
  len(_regions)` (`_prev` still advances, so the tick after the segment text
  lands commits immediately). Cost: a ~1s typing pause per Tier 1 cut, i.e.
  every 30s. The M12 ordering test was rewritten to assert this.
- `LiveTyper.on_commit(chunk)` is the injection seam, called INSIDE `_lock` so
  the app receives chunks in exactly the order `text()` reports them. The
  joining space rides on the FOLLOWING chunk (`"hello there"`, then `" my"`).
  `_run` wires it to `inject.type_text`.
- `inject.type_text(text)` types with NO modifier wait - the hotkey's Alt is
  physically down for a whole hold, so `_wait_modifiers_released` would stall
  every commit for its full 1.5s timeout. Safe because pynput sends characters
  as KEYEVENTF_UNICODE (modifier state is irrelevant) and M11's
  `clear_modifiers` already told the app Alt is up. `inject.patch_text(n,
  retype)` DOES wait: backspace is a real VK and Alt+Backspace is "undo" in
  plenty of apps.
- `LiveTyper.close(id)` (called from `_stop_dictation` and `_cancel_dictation`
  inside `_produce_lock`) blocks further preview commits. Without it a decode
  that started while recording lands seconds later and types words AFTER the
  final patch - unrecoverable text. It deliberately does NOT block
  `on_segment_text`: those are authoritative, arrive before `_finish_dictation`
  on the same worker thread, and must be typed to keep `typed_for()` equal to
  what is actually on screen.
- `_finish_dictation` takes `dictation_id` and asks `livetyper.typed_for(id)`.
  Non-empty -> `patch_plan(typed, final)` -> `patch_text`, no paste at all,
  `injected = True` (the words are in the app either way, so history and the
  AT-4 sample still record). Identical typed vs final sends ZERO keystrokes.
  Empty -> the untouched v1.1 paste.
- Silence path: if the final pass produced nothing but the preview had typed
  something (a hallucinated tail, a VAD-gated window), it is backspaced away.
  Leaving it would put words in the document no dictation produced.
- Esc: `_handle_segment` returns early on `cancelled`, so no patch ever runs -
  typed text stays, exactly as specified.
- Asking the LiveTyper (not the `live_typing` flag) for the typed text is what
  makes a mid-dictation toggle honest: the answer is what was actually typed.
- `live_typing = true` (config + Settings "Type words live while dictating",
  live-appliable, in RESET_ALL_KEYS). `app.set_live_typing(on)` is the one
  switch: it sets the flag AND `_gate.tap_max_s = 0` (every key-up becomes a
  hold release = no toggle mode). `_grab_keyboard` returns early when off (no
  suppression), and `_run`'s `is_dictating` hook includes `app.live_typing`, so
  the preview loop never decodes and never burns GPU. That is the full v1.1
  restore, in three places.
- Tests: 279 pass (was 271). New: commit chunks concatenate to `text()`,
  `close` drops late commits + `typed_for` id guard, the rewritten append-only
  cut test, and four app-level tests (patch instead of paste, identical =
  nothing sent, silence takes typed text back, v1.1 paste when the preview
  never ran) plus the `live_typing` off interaction shell and the close-on-stop
  ordering.
- Live sign-off still owed: the DoD below, plus M11's and M12's.
