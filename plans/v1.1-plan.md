# LocalFlow v1.1 Plan (planned 6 July 2026)

Five milestones, M6 to M10, continuing v1's numbering. Each is independently
shippable and committed on its own. Build in this order; later milestones
depend on earlier ones where noted.

Gate 0 (before starting): Jeremy's live v1 sign-off, AT-4 and AT-6, checklist
in `docs/m4-results.md`. v1.1 work must not start on an unsigned v1 unless
Jeremy explicitly says to skip it.

## What Jeremy asked for (locked decisions)

- Faster load. Today launch-to-ready is 14-19s (log-measured: ~5-7s Python +
  imports, ~3s Whisper GPU compile with warm cache, 5-11s warmup pass).
- Better voice detection and noise filtering. Calibration and sensitivity
  must be adjustable in settings.
- Learn from corrections to his transcripts (fully local).
- A real settings panel (not notepad on the toml). Environment-based presets.
- Pill: option to hide it, with "while dictating" auto-show mode. Movable,
  but NOT too easily: hold left-click for 1 second to unlock dragging.
  An easy reset back to the default position.

## M6 - Faster startup (no new UI, quick win)

Goal: hotkey and mic live in ~6-7s instead of 14-19s. Same warm performance.

Changes, all in `localflow/desktop/app.py` (+ small `core` touches):
1. Reorder `_run()`: after the SttEngine builds (the one thing dictation
   can't start without), immediately open the recorder, start the hotkey
   listener, start the mic watcher, and show the overlay as ready.
2. Move `VadGate()` construction AND the `warmup()` pass onto a background
   thread. Expose a `threading.Event` (`warm`) set when both finish.
3. The worker's `_process()` waits on that event before its first transcribe
   (a dictation in the first seconds just runs a little slower - it must
   never crash or drop). VAD is accessed via the app, not captured early, so
   the worker sees the late-built VadGate.
4. Pill shows "warming up..." state until the event sets, then flashes ready.
5. Log a one-line startup breakdown: interpreter+imports (measured from a
   module-load timestamp), engine build, to-hotkey-live, to-fully-warm.

NOT doing: import-time micro-optimization (numpy/openvino are needed on the
critical path; the ~5-7s interpreter+import cost is capped and not worth the
fragility this round).

Definition of done:
- Log shows hotkey live <= 8s after process start on this machine.
- A dictation during warmup still pastes correctly (manually verified once).
- All existing tests pass; new unit test covers "worker waits for warm event".

## M7 - Pill v2: visibility modes, hold-to-drag, reset

**REVISED mid-build (6 Jul, Jeremy live feedback on the first M7 cut):**
1. NO "hidden/never" option in any menu. Visibility = "always" |
   "dictating" only. (Config still accepts "never" and
   overlay_enabled=false for --no-overlay compat, but no UI offers it.)
2. In "dictating" mode the pill hides IMMEDIATELY on idle - no 1.5s
   linger, no brief idle-chip re-show after the paste.
3. Hold-1s-to-drag is OUT. Instead the right-click menu gets "Unlock
   position": the next left-drag moves the pill (green tint while
   unlocked), release saves the spot and relocks. Plus "Reset position"
   in the same menu.
4. The pill right-click menu must carry everything the tray menu has
   (status, cleanup toggle, pill visibility, unlock/reset position,
   open settings file, quit).
5. A real settings MENU (window) is expected - that is M8, unchanged.

**REVISED round 2 (6 Jul, Jeremy on the rebuilt cut):**
6. Pill right-click menu = ONLY "Unlock position", "Reset position",
   "Settings", "Quit". Cleanup toggle + pill visibility move into the M8
   settings window (tray keeps them meanwhile).
7. The menu appears ABOVE the pill and must not cover it (pill stays
   visible at the bottom of the same window, menu panel floats above
   with a gap).
8. Fewer words everywhere; pill and text BIGGER by default, and M8's
   settings window gets a pill-size option (config key `pill_size`,
   added in M7, default 1.0 on the new larger base sizes).

The spec below is the original; where it conflicts, the revisions win.

All in `localflow/desktop/overlay.py`, `tray.py`, `config.py`.

Visibility. New config key `overlay_visibility = "always" | "dictating" |
"never"` (default "always"). `overlay_enabled = false` keeps working and maps
to "never". Behaviour:
- always: current behaviour (idle chip stays on screen).
- dictating: window withdrawn when idle; deiconifies on rec/busy/menu/ready;
  withdraws again ~1.5s after returning to idle (so the paste is seen to
  finish). The overlay thread and Tk root always exist - only the window
  hides - so mode switches are instant and the settings window (M8) has a UI
  thread to live on regardless of mode.
- never: window withdrawn permanently, thread still up.
Tray menu gains a "Show pill" submenu or three checkable items (always /
while dictating / hidden) writing the choice back to the config file.

Hold-to-drag (Jeremy: deliberately NOT easy to move):
- On ButtonPress-1, start a 1000ms `after()` timer and record the press
  point. If ButtonRelease-1 fires first AND the cursor stayed within a small
  slop (~6px scaled): it's a click - exact current toggle/menu behaviour.
- If the timer fires while still held: enter drag mode. Visual cue: capsule
  border/glow color change so Jeremy knows dragging is armed. B1-Motion then
  moves the window (root.geometry with the press-point offset); release ends
  the drag, saves `overlay_position = [x, y]` (logical px) to the config,
  and does NOT toggle dictation.
- Moving before the second is up cancels the timer and does nothing (prevents
  accidental drags); the release still counts as a click only if within slop.
- On startup, a saved position is clamped to the current virtual screen so a
  monitor change can't strand the pill off-screen.
Keep the state machine as a small testable class (pure logic, no Tk) so the
click/drag/cancel paths get unit tests.

Reset position:
- Tray menu item "Reset pill position" + a button in the settings panel (M8).
- Reset = drop `overlay_position` from config, snap back to bottom-center.

Definition of done:
- Unit tests for the click-vs-hold-vs-drag state machine and position
  clamping. Existing overlay behaviours (click-to-dictate, right-click menu,
  never steals focus) unchanged - live sanity check.
- Live: drag works only after a 1s hold, reset restores bottom-center,
  "while dictating" mode shows the pill only during dictation.
- Config round-trips: position and visibility survive a restart.

Known trap: the Tk root must still be torn down on its own thread (Tcl
abort). All new window ops go through the existing command queue.

## M8 - Real settings window

New module `localflow/desktop/settings_ui.py`. The settings window is a
normal, focusable Toplevel owned by the overlay's existing UI thread (single
Tk root per process - the pill and settings share it; the overlay thread now
always exists per M7). Opened from the tray menu ("Settings...") and the
pill's right-click menu, replacing open-notepad. Keep "Open settings file"
in the tray as an advanced escape hatch.

Config writing: add `tomlkit` (new dependency) for comment-preserving
round-trip writes to `localflow.toml`. All writes funnel through one
`config.save_config(path, changes: dict)` helper with tests.

Live-apply plumbing in `app.py`: one `apply_settings(new_cfg)` entry that
diffs against the running config and applies what it can without restart:
- hotkey: stop and rebuild PushToTalkListener.
- denoise/normalize/strength: swap in a new AudioPreprocessor.
- vad sensitivity (M9 key): set on the VadGate.
- restore_delay_ms, inject_mode: plain attribute updates.
- input_device: pin/unpin + recorder.refresh_default_device().
- overlay_visibility / position reset: overlay commands.
- cleanup on/off: existing toggle path.
Restart-only (shown with a "takes effect on restart" note): device
(GPU/NPU/CPU), model dirs, cache dir, hot_words.

Panel contents (sections top to bottom, or tabs if it gets tall):
1. Microphone: dropdown of WASAPI input devices + "System default (follow
   Windows)" as the first entry; live level meter (fed by the same
   recorder.on_level fan-out as the pill); "Test mic" button = capture ~3s,
   run the real pipeline, show the transcript inline. Shows a warning row
   when the fallback mic is active (recorder.fallback_active).
2. Environment preset: dropdown - Quiet room / Noisy room / Headset /
   Custom. A preset just sets the two sliders below (and normalize), and
   the label flips to Custom the moment a slider is hand-moved. Starting
   values (tune live in M9): Quiet 0.3 denoise / 0.5 sensitivity; Noisy
   0.75 / 0.6; Headset 0.2 / 0.45.
3. Audio tuning: denoise strength slider (0-1), speech sensitivity slider
   (VAD threshold, wired in M9), normalize toggle, "Calibrate room noise"
   button (M9 - disabled with a tooltip until then).
4. Hotkey: press-to-capture box. Click it, it says "press your combo...",
   a temporary pynput listener records the pressed combo, it is validated
   via HotKey.parse and displayed; Esc cancels. Apply rebuilds the listener.
5. Behaviour: pill visibility dropdown, "Reset pill position" button,
   paste vs type mode, clipboard restore delay.
6. Cleanup: on/off (same lazy load/unload path), model status line, memory
   note.
7. Advanced (restart needed): device GPU/NPU/CPU, model folder, cache dir.
8. (M10 adds: Dictionary and History sections.)

Definition of done:
- Settings opens from tray and pill menu, edits write to localflow.toml
  preserving comments, live-appliable settings take effect without restart
  (hotkey change verified live), restart-only ones show the note.
- Unit tests: save_config round-trip preserves comments/unknown formatting;
  apply_settings dispatches the right actions from a diff (mock app parts).
- The pill and dictation keep working with the settings window open
  (no focus steal from the pill, no Tcl thread violations).

## M9 - Noise and voice detection upgrade

1. Sensitivity: new config key `vad_threshold` (default 0.5, range 0.3-0.7
   exposed as the slider). Plumb into VadGate; live-apply.
2. Noise calibration: "Calibrate room noise" in settings records 2s from the
   current mic (must be quiet - level meter shown, warn if speech detected),
   computes the per-frequency noise floor (same STFT parameters as
   reduce_noise), saves to %LOCALAPPDATA%\LocalFlow\noise_profile.npz with
   the device name. reduce_noise() gains an optional `noise_floor` argument:
   when a profile exists for the active mic and denoise is on, the gate uses
   the calibrated floor instead of the per-clip percentile estimate (better
   when the clip is mostly speech). Falls back to per-clip automatically if
   the profile's mic doesn't match the active one. "Clear calibration"
   button next to it. Core change stays pure (profile passed in from the
   desktop layer - core does no file I/O).
3. DeepFilterNet spike (timeboxed to one session): evaluate the local neural
   denoiser on CPU on this machine - install weight (it drags in torch),
   latency per 5s utterance, and A/B quality vs the spectral gate on
   recorded real-mic samples (quiet room + fan/keyboard noise). Adopt ONLY
   if latency <= ~150ms per utterance and the transcripts are clearly
   better; then it becomes `denoise_backend = "spectral" | "deepfilter"`
   with spectral as default-safe. If torch is too heavy or slow, record the
   numbers, keep the improved spectral path, and close the spike. Check with
   Jeremy before adding the dependency.
4. Do the still-pending denoise A/B on the real mic while at it (deferred
   from the 6 Jul handoff) and pick the default denoise_strength properly.

Definition of done:
- Sensitivity slider audibly changes gating behaviour (live test: quiet
  speech accepted at low threshold, background noise gated at high).
- Calibration measurably improves a noisy-room transcript (record one fixed
  sentence with fan noise, with and without profile, compare).
- Unit tests: reduce_noise with an injected noise floor; profile save/load
  and mic-mismatch fallback.
- Spike verdict written into this plan's log section (adopt or not, numbers).

Known trap: do NOT touch hot_words for accuracy (a populated list degraded
accuracy live on 3 Jul). All accuracy work here is audio-side or post-text.

## M10 - Learning loop: history + personal dictionary

The constraint (explained to Jeremy): LocalFlow cannot see edits made in the
target app after pasting, so corrections happen in a History panel.

1. History store: `%LOCALAPPDATA%\LocalFlow\history.jsonl`, one line per
   pasted utterance: timestamp, raw_text, clean_text, final_text (what was
   pasted), corrected_text (null until Jeremy edits), device, stt_ms. Capped
   at 200 entries (rewrite-on-cap). New config keys: `history_enabled = true`
   (off = store nothing), and a "Clear history" button. Fully local, same
   privacy stance as everything else.
2. History section in settings: most-recent-first list, each entry editable
   in place; saving an edit stores corrected_text and immediately feeds the
   dictionary miner.
3. Personal dictionary: a `[replacements]` table in localflow.toml (e.g.
   "code x" = "Codex"). Applied AFTER STT and after cleanup, deterministic
   word-boundary, case-preserving replacement in a new pure-core function
   (`core/dictionary.py` - text in, text out, no I/O). Editable as a simple
   two-column list in settings. Zero STT-accuracy risk, unlike hot_words.
4. Miner: on each saved correction, word-level diff original vs corrected;
   a substitution seen >= 2 times across history becomes a SUGGESTED rule
   shown in the dictionary section (one click to accept, never auto-applied).
   Keep it dumb and transparent - no ML, just counting.
5. Stretch (only if the rest lands early): corrections as few-shot examples
   in the cleanup LLM prompt when cleanup is on.

Definition of done:
- Unit tests: dictionary application (word boundaries, case, multi-word,
  overlap ordering), miner diff/count/suggest, history cap and round-trip.
- Live: dictate, correct an entry in History, see the suggestion appear,
  accept it, dictate the same phrase, pasted text has the fix applied.
- With history_enabled = false nothing is written to disk.

## Cross-cutting rules

- Core seam stays pure: dictionary and noise-floor logic take data in and
  return data out; all file I/O lives in the desktop layer.
- Fully local, as ever. The DeepFilterNet model, if adopted, is downloaded
  once at install time like Whisper was - never at runtime.
- ASCII-only console output, crash-proofed callbacks, Tcl teardown on the
  UI thread, no per-keydown stream opens - all v1 traps still apply.
- New dependencies this plan may add: tomlkit (M8, definite), deepfilternet
  + torch (M9, only if the spike passes and Jeremy approves).
- Tests: every milestone extends `tests/` and the full suite must pass
  before its commit. Current baseline: 57 passing.
- One commit per milestone minimum, message style matching v1 history
  (`feat(m6): ...`).

- **Tier 1: VAD-segmented streaming transcription (6 July 2026, this
  session).** Build request from the long-dictation handoff. While the hotkey
  is held, a background segmenter cuts a long hold at a recent silence and
  transcribes that piece DURING the hold, so the wait on release stays short no
  matter how long you talk (bounds the ~14s/90s buffer latency to roughly one
  final segment). Cutting at silence means the per-segment texts join back
  cleanly with no overlap-stitching.
  - **Pure core:** `core/segment.py` `find_cut_point(spans, total, ...)` picks
    the MIDPOINT of the LAST qualifying silence gap (min_gap 0.6s, min_lead 5s,
    edge_guard 1s so the live edge — maybe still speech — is never cut). Leading
    silence never qualifies; all-silence returns None. Exported from
    `localflow.core`; stays pure (imports only `.audio`).
  - **VadGate.speech_spans()** (core/vad.py): raw (start,end) spans for the
    segmenter, separate from trim(). The segmenter gets its OWN VadGate
    (get_speech_timestamps mutates Silero state — never share the worker's).
  - **Recorder (capture.py):** `buffered_frames()`, `snapshot()` (lock-cheap
    copy, concat outside the lock), `drain_segment(up_to_frame)` returns the
    front and KEEPS the tail as the next segment's start (contiguous), empty if
    not recording so a stop() race emits nothing.
  - **Segmenter (desktop/segmenter.py):** polls every 1s while recording; once
    the buffer passes `segment_seconds` it snapshots -> resamples to 16k ->
    VAD spans -> find_cut_point -> maps the cut back to native frames -> asks
    the app to drain+enqueue. No silence found past `segment_seconds`+15s ->
    force a cut at the target (accept a rare mid-word split). Private VAD built
    + thread started from the warmup thread (after `app.warm`).
  - **Worker (app.py):** work items are now `_Segment` (mid vs final). Mid
    segments transcribe raw (no cleanup) and accumulate ordered texts under a
    `dictation_id`; the on-release final joins them and runs cleanup +
    dictionary + inject + history ONCE. `emit_segment(cut, id)` + `on_hotkey_up`
    both drain+enqueue under `_produce_lock`, so a mid cut can never land after
    the final (ordering guaranteed). Legacy 3-tuple queue puts still work
    (treated as a single-segment final). Short dictations (< segment_seconds)
    are one segment on release = EXACTLY the old behaviour.
  - **Config:** `segment_seconds` (default 30.0, 0 = off, validated 0 or
    10-600), live-appliable (`hook_segment_seconds` -> segmenter). Settings
    "Segment length (s)" spinbox in Behaviour; in RESET_ALL_KEYS. With
    segmentation on, draining keeps the buffer small so `max_utterance_s` never
